`docs/requirements.md` 가 정하지 않은 부분을 어떻게 정했는지, 왜 그렇게 했는지 짧게 남긴다.

## 2. 녹화

- **설치 보장**: 캡처는 `addInitScript` 로 넣고, 문서가 바뀔 때마다(`framenavigated`, `domcontentloaded`) 다시 `evaluate` 로 설치를 확인한다. 실제로 `window.open` 창은 빈 문서의 window 가 재사용되어 문서 시작 스크립트가 진짜 문서에 붙지 않는 것을 확인했다. 그래서 설치 표시는 `document` 에, 공용 상태(이벤트 번호, 마지막 동작)는 `window` 에 둔다. Node 연결 함수(`exposeBinding`)가 없는 문서에서는 이벤트를 쌓아 두고 0.4초마다 가져온다.
- **사람의 동작만**: `isTrusted` 이벤트만 쓴다. 예외로 값 변경(`input`·`change`)은 신뢰 이벤트가 아니어도 **호출 스택에 페이지 스크립트(http·file·blob 주소)가 없으면** 사람(자동화 도구 포함)의 동작으로 본다. Playwright 의 `selectOption`·날짜 칸 `fill` 은 신뢰 이벤트를 만들지 않기 때문이다. 사이트 스크립트가 일으킨 값 변경은 스택에 사이트 주소가 남아 버려진다.
- **입력**: 칸마다 마지막 값 하나. 입력은 0.3초 모았다가 보내고, 다른 동작(클릭·키) 직전과 포커스를 잃을 때, `stop()` 때 바로 보낸다. 마지막 스텝이 같은 칸이면 값만 바꾼다. 비밀번호 칸은 값을 보내지 않고 `{{라벨}}` prompt·secret 변수를 만든다(같은 이름이면 같은 변수).
- **클릭이 아닌 것**: 체크박스·라디오·파일 칸·select·라벨(연결된 칸이 있는 것)·편집 가능한 입력칸 클릭은 버린다. 결과는 `change` 가 `check`/`upload`/`select` 로 남긴다(라벨을 눌러도 대상은 실제 입력 요소). Enter 직후 1초 안의 `detail=0` 클릭(암묵적 제출·키보드로 누른 버튼)은 keypress 가 대신하므로 버린다.
- **더블클릭**: `detail≥2` 클릭은 버리고, `dblclick` 이벤트가 오면 1.5초 안의 같은 요소 클릭 스텝을 `dblclick` 으로 바꾼다.
- **파일 선택창**: 버튼 클릭 처리 중 스크립트가 숨은 파일 칸을 누르면(신뢰 아님) 그 클릭을 표시해 두고, 그 칸의 `change` 가 오면 클릭 스텝을 `upload`(대상은 버튼)로 바꾼다. 재생 때 버튼을 눌러 선택창에 넣는다.
- **다운로드**: 0.5초 기다린 뒤(원인 클릭이 먼저 도착하도록) 다운로드 시작 시각 이전의 가장 최근 `click` 을 `download` 로 바꾼다. 입력·선택 같은 스텝은 건너뛰고 거슬러 올라가므로 서버가 오래 걸려 늦게 시작된 다운로드도 찾는다(최대 5분). Enter·더블클릭·이동을 먼저 만나거나 못 찾으면 `warn`.
- **알림창**: `alert/confirm/prompt` 를 감싸 사람이 고른 응답을 기록한다. 원인은 그 순간의 마지막 동작 번호 → 그 스텝 **앞**에 넣는다(`meta.triggerStepId`). 같은 원인에 여러 개면 뜬 순서대로 앞에 쌓인다. 녹화 중 알림창은 Node 가 응답하지 않는다(빈 `dialog` 리스너만 두어 Playwright 가 자동으로 닫지 않게 한다).
- **인쇄**: `window.print` 를 바꿔 실제 인쇄창 없이 원인 동작 바로 뒤에 `pdf` 스텝을 넣는다.
- **팝업 닫힘**: 사이트가 연 창이 닫히면 0.3초 뒤 `closeTab`. 다운로드만 하고 닫힌 창, 문서를 한 번도 열지 않은 빈 창은 뺀다. 늦게 도착한 이벤트는 시각 순서 자리에 끼운다(창이 닫히며 마지막 클릭이 늦게 오는 경우).

## 3. 타겟 후보와 점수

녹화 시점에 그 요소 **하나만** 가리키는 후보만 넣는다(글자 후보만 예외로, 여러 개면 점수 5~19 로 남긴다). 점수는 순서만 뜻한다.

| 후보 | 점수 |
|---|---|
| 안정된 `#id` | 95 |
| `data-testid` 등 테스트 속성 | 93 |
| 라디오·체크박스 `name`+`value` / `name` | 90 / 88 |
| `aria-label` | 84 |
| 라벨로 찾는 XPath (`//input[@id=//label[…]/@for]`, `//label[…]//input`) | 82 / 81 |
| 바뀌는 id 의 안정된 앞부분 `[id^=…]` / 앞뒤 / 뒷부분 | 80 / 78 / 76 |
| `placeholder` | 80 |
| 보이는 글자 `{ tag, text }` (60자 이하, 입력칸 제외) | 75 |
| `a[href]` (쿼리 없는 고정 주소) | 72 |
| `title`·`alt`·`part` | 70 |
| 표 줄 기준 XPath (`//tr[*[1][normalize-space()='가']]//button[…]`) | 68 |
| 구조 CSS 경로 (안정된 id 조상부터, `:nth-of-type`) | 55 |
| 절대 XPath | 40 |
| 바뀌는 `#id` 그대로 | 30 |

- **바뀌는 id**: 4자리 이상 숫자 덩어리, 숫자·글자가 섞인 6자 이상 16진수, 16자 이상 해시, UUID, React `:r1:`. 구분자(`-_:.`) 앞의 안정된 부분으로 대안 후보를 만든다.
- **실행 때 덧붙이는 후보**(녹화 후보 뒤에): `#바뀌는id` → `[id^=앞부분]`, `meta.label` 로 라벨 XPath·`aria-label`·`placeholder`, 글자 후보가 없으면 `meta.text`. 값 읽기와 `exists` 조건에는 글자로 넓히지 않는다(행마다 글자가 바뀌고, 존재 판정이 느슨해지므로).
- 섀도 DOM: 찾기는 문서와 모든 열린 섀도 루트를 함께 본다(XPath 제외). 그래서 섀도 안 요소도 글자·속성 후보로 유일하게 찾힌다.

## 4. 찾기와 대기

- 0.2초 간격으로 후보를 점수 순으로 센다. **보이는 것이 정확히 하나**인 후보를 쓴다. 보이는 것이 없고 전체가 하나인(숨은) 후보는 **2.5초** 더 기다려도 보이는 것이 없을 때만 쓴다(그때는 스크립트 클릭).
- 기본 대기 10초, `optional` 은 2초, `timeoutMs` 가 있으면 그 값. 못 찾았는데 문서가 아직 `complete` 가 아니면 불러오기를 기다려 3초 더 찾는다(아직 아무것도 하지 않은 경우만).
- 프레임 경로는 이름 → 주소(정확히, 다음은 쿼리 무시) → 순번. 따라갈 수 없으면 모든 프레임의 합계로 유일성을 본다. 경로는 맞는데 그 안에 없을 때도 모든 프레임 합계로 한 번 더 본다.
- 못 찾으면 후보별 맞은 개수를 담은 오류: `요소를 찾지 못했습니다: "조회" 버튼. 시도한 후보: css #x → 0개 · text <button>"조회" → 2개`.
- `wait` 기본 10초(optional 2초), `assert` 기본 2초(늦게 뜨는 글자·알림 대비), `branch` 는 즉시 판정하되 알림 문구 조건이면 1.5초까지 기다린다.

## 5. 동작

- **클릭**: Playwright 클릭(준비 대기 5초). 준비 시간 초과·가려짐처럼 **아직 누르지 않은** 실패만 스크립트 클릭으로 대신한다. 호출 기록에 `click action done` 이 있으면 이미 누른 것이므로(뒤따른 이동 대기가 길었을 뿐) 성공으로 본다. 스크립트 클릭 뒤 0.8초 동안 DOM 변화·주소·탭 수·알림창·다운로드 중 하나도 바뀌지 않으면 실패. 누른 뒤 창이 닫혀도 성공. 찾은 요소가 그새 다시 그려졌으면(DOM 에서 떨어짐) 한 번 더 찾는다.
- **재시도**: `attempts` 만큼. 다운로드·PDF·첨부·알림창·분기·확인 대기·팝업 닫기는 재시도하지 않는다. 부작용이 이미 났을 수 있는 실패(`sideEffect`)는 횟수가 남아도 다시 하지 않는다.
- **입력**: `fill` → 값 확인. 공백만 다르거나, 화면 값이 숫자·구분자만이고 숫자가 같으면(마스크 칸) 반영된 것으로 본다. 아니면 지우고 실제 키 입력(20ms 간격)으로 다시. 숨은·읽기 전용 칸은 네이티브 setter + input/change 이벤트.
- **선택**: 값 → 보이는 글자 → 띄어쓰기 무시(글자, 값) 순. **체크**: 이미 원하는 상태면 누르지 않는다. 6px 미만이거나 투명한 커스텀 체크박스는 연결된 라벨 클릭 → 스크립트 클릭 순으로 시도하고 매번 상태를 확인한다.
- **대화상자 방침**: `dialog` 스텝은 방침을 대기열에 넣고, 뜨는 알림창이 차례로 꺼내 쓴다(행마다 비움). 방침이 없으면 알림·페이지 나가기는 확인, 확인창·입력창은 **취소**(예상 못 한 동작을 승인하지 않는다). 모든 문구를 `lastDialogMessage` 와 `dialogContains` 판정에 쓴다.
- **사람 속도**: `humanPacing` 이면 화면 조작 스텝 앞에 `meta.recordedGapMs`(최대 3초)만큼 쉰다.

## 6. 탭

- 세션이 다루는 탭은 **업무 탭 + 사이트가 연 창(popup 이벤트)** 뿐이다. 브라우저가 스스로 만든 빈 탭은 무시한다 — Edge 는 다운로드용 팝업이 닫힌 뒤 주소가 빈 탭을 하나 만드는데, 이 탭은 `close()` 가 끝나지 않아 건드리면 실행이 멈춘다(실제로 확인).
- 사이트가 창을 열면 그 창으로 옮기고, 지금 창이 닫히면 직전 창으로 돌아온다. 업무 탭은 `closeTab` 으로도 닫지 않는다. 행 시작 때 업무 탭만 남긴다(닫기는 3초 상한).
- 대상이 지금 탭에 없고 지금 탭 주소가 `meta.url` 과 다르면, 그 주소의 다른 탭에 유일하게 보일 때 바로 옮긴다. 시간이 다 되어도 못 찾으면 대상이 보이는 다른 탭이 하나 있을 때 옮긴다(로그: "대상이 다른 탭에 있어 … 탭으로 전환").

## 7. 다운로드·출력

- 다운로드 스텝은 클릭 **전에** 대기를 걸어 어느 탭에서 시작되든(새 창·새 탭·iframe·늦은 시작) 첫 다운로드를 받는다. 시작 대기 60초(`timeoutMs` 가 더 크면 그 값), 끝날 때까지 기다린 뒤 실패·빈 파일은 오류.
- 이름: `fileName` 이 있으면 변수 치환 + 원래 확장자, 없으면 사이트가 준 이름. `safeFileName` 후 `files/` 에 **독점 생성(`wx`)으로 자리를 잡아** ` (1)`, ` (2)` … 를 붙인다(동시에 같은 이름을 잡지 않게).
- 다운로드 때문에 새로 열린 창(빈 창·스스로 닫히는 창)은 받은 뒤 닫고 클릭한 창으로 돌아온다.
- PDF: 숨김 실행은 `page.pdf`(A4, 배경 포함, 여백 10mm), 화면 표시 실행은 전체 화면을 A4 비율로 잘라 캡처해 pdf-lib 로 묶는다(최대 40쪽). 저장 전 `settleMs`(기본 0.5초) 기다리고, 저장 뒤 `%PDF-` 머리와 pdf-lib 로 쪽 수를 확인한다.
- 파일 이름 정리: 금지 문자 → `_`, 끝 점·공백 제거, 예약 이름 앞에 `_`, 150자 제한(확장자 유지), 비면 오류.

## 8. 브라우저 실행 인자

- `--disable-blink-features=AutomationControlled` 와 `ignoreDefaultArgs: ['--enable-automation']`: `navigator.webdriver` 가 `false` 가 되고 "자동화 소프트웨어가 제어 중" 표시가 사라진다. 사이트가 자동화 브라우저라고 다르게 동작하지 않게 한다(확인함: 숨김·표시 모두 `false`).
- `--disable-background-timer-throttling`, `--disable-backgrounding-occluded-windows`, `--disable-renderer-backgrounding`: 다른 창에 가려지거나 뒤로 간 탭에서도 타이머·렌더링이 느려지지 않게(Playwright 기본값과 겹치지만 의도를 분명히 하려고 명시). `--disable-features` 는 Playwright 가 이미 쓰는 목록을 덮어쓸 수 있어 넣지 않았다.
- 화면 표시 모드는 `viewport: null` + `--window-size=1400,960`(사람이 창을 키우면 페이지도 커지게), 숨김 모드는 1366×900 고정. `locale: ko-KR`, 다운로드 허용.
- 실행 파일은 `executablePath` 로 지정한다(Edge·Chrome·Brave·직접 지정을 같은 방식으로). 자동 선택은 Edge → Chrome → Brave → Playwright Chromium.
- 프로필 사용 중: Windows 는 프로필의 `lockfile` 을 열어 보고(브라우저가 독점으로 연다), 실행 오류 문구도 함께 보아 "브라우저 프로필이 이미 사용 중입니다…" 로 알린다.
- 컨텍스트에 `__channel`(사람이 읽는 이름, 예: `Brave`)을 붙이고 실행 기록에 버전과 함께 남긴다.

## 9. 상한·기타 값

- 블록 호출 중첩 12단계, 한 행 스텝 3000개(무한 분기 방지).
- 변수: 예약 이름 → 값 읽기 결과 → 변수(id, 이름) → 엑셀 열(정의 없이 열 이름을 바로 쓴 경우) 순. 정의되지 않으면 오류(관찰기만 빈 값). 조건 안에서는 거짓. `{{sys:month}}`·`{{sys:day}}` 는 앞자리 0 없이(`9`, 이전 버전과 같게. 두 자리는 `{{sys:date:MM}}`), `{{sys:quarter}}` 는 `3분기`. `|default:x` 가 있으면 정의 안 된 변수도 x.
- 로그 줄: `[HH:MM:SS] 메시지`, 경고·오류는 `[warn]`·`[error]` (화면이 이 표시로 색을 입힌다). 비밀 변수가 든 입력값은 오류 문구에서 `••••` 로 가린다.
- AI 관찰: 지정 스텝 실행 뒤 DOM 이 0.8초 잠잠해질 때까지(최대 5초) 기다리고 목록을 만든다. 프레임당 250개, 전체 600줄. 줄 형식 `f0e12 button "선택" row="가" col="…"` — 표 안 요소는 같은 줄 첫 글자 칸(`row`)과 열 머리글(`col`)을 붙인다. 되돌릴 수 없는 버튼은 녹화 이름과 실제 화면 글자(20자 이하)에서 `제출·신고·결제·삭제·발송·송금·이체·전송·해지·탈퇴·승인·확정·구매·주문·계약` 등으로 판단한다.

## 10. 진행 세트·허브 (0.2.0)

- **같은 규칙, 한 곳**: 정리·위험·개인정보·manifest·세트 검사는 허브 CI 와 같은 `core.mjs`, 압축은 `zip.mjs` 를 그대로 쓴다. 엔진 쪽 차이는 레시피 검사기만 넘기는 것이고, 이때 "첨부할 파일 경로가 비어 있음"은 빼고 넘긴다(공유하며 경로를 비우는 것이 규칙이라 설치한 사람이 채운다 — 그 전까지 실행 전 검사가 막는다).
- **결정적 묶기**: `buildSet` 은 manifest·recipe·README·sample·expected 를 만든 뒤 `folder.mjs` 의 `packFiles`(= 이름 순서 `writeZip`)로 묶는다. 풀었다 다시 묶어도(`set unpack` → `set pack`) 같은 sha256 이 나오는 것을 시험한다. 폴더 묶기는 점으로 시작하는 파일·Thumbs.db·desktop.ini 만 빼고 바이트는 바꾸지 않는다.
- **README·기대 결과 초안**: README 는 manifest(설명·사이트·열 설명·위험)로만 만든다. 기대 결과 초안은 지난 실행의 성공 행에서 값 이름·값 모양(숫자/금액/날짜 정규식)·파일 확장자만 가져온다 — 녹화·실행의 실제 값이 세트로 새지 않게.
- **설치**: 같은 세트 id 를 다시 설치하면 같은 레시피 id 를 새 버전으로 덮고 이전 파일은 `trash` 에 복사해 둔다(첨부 경로 등 손댄 것을 되찾을 수 있게). 예시 입력은 올린 파일(`uploads/`)로 넣어 실행 화면의 `#/run?recipe=…&upload=…` 로 바로 고른다. 레시피를 지운 세트는 설치 목록에서 빠진다.
- **허브**: 목록은 1분 기억한다([새로 고침]은 다시 받는다). 버전을 고르지 않으면 이 엔진 범위에 맞는 가장 새 버전. 엔진 범위가 맞지 않으면 내려받기 전에 거절하고, 세트 안 manifest 의 범위·id·버전도 다시 본다. 목록·세트·README 는 크기 상한(5MB·2MB·300KB)과 20초 제한으로 받는다. 화면·API 는 설정에 있는 허브만 받는다(임의 주소를 서버가 대신 받지 않게).
- **사이트 제한**: 컨텍스트 경로 가로채기(`context.route`)에 "허용되지 않은 origin" 조건 함수를 걸어, 그중 최상위 프레임의 이동 요청만 `blockedbyclient` 로 막는다(하위 자원·iframe 은 그대로 보낸다). 경로 가로채기는 리디렉션을 거치지 않으므로 `framenavigated` 로 이동한 뒤 주소를 한 번 더 보고, 밖이면 빈 페이지로 돌린다. 막으면 행에 표시해 두고, 다음 스텝 전 확인 지점(또는 행 끝)에서 **신호 오류**로 행을 실패시킨다 — 신호라서 "실패해도 계속"·재시도로 넘어가지 않는다. 막은 이동 때문에 난 스텝 오류(주소를 열지 못함 등)는 막은 이유로 바꿔 남긴다.
- **실행 간격·상한**: 간격은 앞 행이 끝난 때부터 다음 행 시작까지(사이트 부담 기준). 상한을 넘는 행은 시작하지 않고, 리포트에 `limit: { maxRowsPerRun, nextRow, skipped }` 와 "시작 행을 N 으로 정해 이어서 실행" 문구를 남기며 상태는 `stopped`(실패 행이 있으면 `failed`). 세트가 적은 값은 0~10분, 1~100000행으로 자른다.
- **명령줄**: 종료 코드 0 성공 · 1 실패 · 2 사용법. `process.exit()` 대신 `process.exitCode` 를 쓴다 — Windows 에서 내려받기 연결이 닫히는 중에 바로 끝내면 Node 가 `UV_HANDLE_CLOSING` 단언으로 죽는 것을 확인했다. 설치본 `web-rpa.cmd` 는 첫 인자가 `set`·`hub` 면 앱 폴더로 옮기지 않고 `cli.js` 를 부른다(파일 경로가 지금 폴더 기준이 되게, `WEB_RPA_CWD`).

## 11. 빠진 것·알려진 한계

- 숨김 모드의 사용자 에이전트에는 `HeadlessChrome` 이 그대로 남는다(바꾸려면 버전을 알아야 해 실행을 두 번 해야 한다). 숨김 브라우저를 막는 사이트는 화면 표시 모드로 실행해야 한다.
- 다른 출처(cross-origin) iframe 안에서 뜬 알림창은 그 문서의 갈고리로만 잡힌다. 페이지가 `alert` 를 미리 다른 이름으로 저장해 두면 녹화에서 놓칠 수 있다.
- 닫힌 섀도 루트 안 요소, 캔버스로 그린 화면은 찾지 못한다.
- 한 번의 클릭으로 파일이 여러 개 받아지면 첫 파일만 저장한다(녹화 때 경고).
- 녹화 중 주소창에 직접 친 이동, 마우스 끌기·휠, Tab 키 이동은 기록하지 않는다.
- 허브 목록 서명은 아직 없다(https + sha256 만). 세트 사이트 제한은 AI 화면 관찰(Observer)에는 걸지 않았다.
